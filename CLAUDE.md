## Project Overview

This repository implements research on neural networks learning quantum and post-quantum representations. The codebase trains neural networks (Transformers, LSTMs, GRUs, RNNs) on sequences generated by Generalized Hidden Markov Models (GHMMs), then analyzes whether the networks learn to represent belief states about the hidden states of these processes.

### Current Status Notes

- Bloch/quantum belief regression is only reaching R² ≈ 0.5 with the lightweight pipeline. The published results report R² ≈ 1.0, so we need to revisit the regression/regularization settings to close the gap in a future pass.

**Key Concept**: The core hypothesis is that neural networks trained on sequential data from stochastic processes learn to represent "beliefs" (probability distributions) about the underlying hidden states. The pipeline compares these learned representations against both theoretical quantum/classical belief states and Markov approximations.

## Architecture Overview

### Core Components

1. **GHMM (Generalized Hidden Markov Model)** (`epsilon_transformers/process/`)
   - `GHMM.py`: Abstract base class for GHMMs with transition tensors `T(a, h', h)` representing probability of transitioning from hidden state `h` to `h'` while emitting symbol `a`
   - `transition_matrices.py`: Implementations of specific processes:
     - `mess3`: Classical process
     - `tom_quantum` (Bloch Walk): Quantum process
     - `post_quantum` (Moon Process): Post-quantum process
     - `fanizza` (FRDN): Quantum process
   - `MixedStateTree.py`: Tree data structure representing belief states at each sequence prefix
   - Key method: `markov_approximation()` creates finite-order Markov chains that approximate the GHMM

2. **Neural Network Training** (`epsilon_transformers/training/`)
   - `networks.py`:
     - `RNNWrapper`: Wraps PyTorch RNN/LSTM/GRU with one-hot input encoding
     - `create_RNN()`: Factory for creating RNN models
     - `forward_with_all_states()`: Critical method that extracts hidden states at all layers and timesteps
   - `train.py`: Training loop for Transformers using HookedTransformer from TransformerLens
   - `train_rnn.py`: Training loop for RNN models
   - `dataloader.py`: Data generation from GHMM processes
   - `generate_data.py`: Loads or generates process data
   - `logger.py`: WandB integration for experiment tracking

3. **Activation Analysis Pipeline** (`scripts/activation_analysis/`)
   - `run_regression_analysis.py`: **Main analysis script** - processes predefined sweep/run pairs
   - `data_loading.py`:
     - `ModelDataManager`: Loads models and checkpoints from S3 or HuggingFace
     - `ActivationExtractor`: Extracts activations from different architectures
   - `belief_states.py`: `BeliefStateGenerator` creates theoretical belief states from Markov approximations
   - `regression.py`: `RegressionAnalyzer` performs weighted least squares regression mapping activations to belief states
   - `config.py`: Centralized configuration (device settings, sweep IDs, regularization parameters)
   - `utils.py`: Helper functions for standardization and result saving

4. **Analysis and Visualization** (`epsilon_transformers/analysis/`, `epsilon_transformers/visualization/`)
   - `load_data.py`: `S3ModelLoader` for loading trained models from S3
   - `activation_analysis.py`: `prepare_msp_data()` prepares Mixed State Presentation data
   - `plots.py`: Plotting utilities for belief state visualizations
   - `graph.py`: Graph visualizations for GHMM structures

### Model Architectures

The codebase supports 4 neural network architectures:
- **Transformers**: Use TransformerLens's `HookedTransformer` with residual stream activations
- **LSTMs**: Standard PyTorch LSTM with one-hot encoded inputs
- **GRUs**: Standard PyTorch GRU with one-hot encoded inputs
- **RNNs**: Standard PyTorch RNN (vanilla) with one-hot encoded inputs

All models are 4-layer networks trained on 4 different stochastic processes.

### Data Flow

1. **Training Phase**:
   - GHMM processes generate sequences → Neural networks trained to predict next token
   - Models saved to S3 with checkpoints during training
   - WandB logs training metrics and loss curves

2. **Analysis Phase**:
   - Load trained models and checkpoints
   - Generate "ground truth" belief states from GHMM using exact inference
   - Generate Markov approximation belief states (order 3 used in paper)
   - Extract neural network activations for same input sequences
   - K-fold cross-validation (10 splits) with weighted least squares regression
   - Sweep over regularization parameters (rcond values) to find optimal mapping
   - Compute performance metrics: RMSE, MAE, R², distance

3. **Figure Generation**:
   - Load pre-computed analysis results from HuggingFace
   - Visualize belief state comparisons, representational similarity, model performance

### Critical Implementation Details

**Activation Extraction**:
- **Transformers**: Extract from `blocks.{i}.hook_resid_post` and `ln_final.hook_normalized`
- **RNNs**: Use `forward_with_all_states()` to get hidden states at each layer and timestep, concatenate with one-hot encoded inputs
- **Combined Analysis**: Concatenate activations from all layers

**Markov Approximation Algorithm** (`epsilon_transformers/process/GHMM.py:234-285`):
1. Generate all token sequences of length k (Markov order)
2. Filter by probability under GHMM (threshold: 1e-13)
3. Each sequence becomes a state in the Markov chain
4. Transition probability from state s to s': `P(s') / P(s[:-1])`
5. Compute belief states for Markov chain given observed sequences

**Data Deduplication**:
The regression pipeline identifies sequences with identical prefixes and combines them to avoid redundant computation while preserving statistical properties.

**Device Configuration**:
Training uses CUDA. For regression analysis, data extraction uses CPU/CUDA, but regression computation can use CUDA for speedup (configurable in `scripts/activation_analysis/run_regression_analysis.py`).

## Configuration Files

Training experiments are defined in YAML configs:
- `scripts/experiment_config_rnn.yaml`: Sweep over LSTM/GRU/RNN, all 4 processes
- `scripts/experiment_config_transformer_mess3_bloch.yaml`: Transformers on Mess3 and Bloch Walk
- `scripts/experiment_config_transformer_moon.yaml`: Transformers on Moon Process
- `scripts/experiment_config_transformer_frdn.yaml`: Transformers on FRDN

Analysis configuration in `scripts/activation_analysis/config.py`:
- `DEVICE`: Device for data extraction ('cuda', 'cpu', or 'mps')
- `RCOND_SWEEP_LIST`: 53 regularization values from 1e-15 to 1e-3
- `SWEEPS`: Sweep IDs to process
- `TRANSFORMER_ACTIVATION_KEYS`: Which residual stream positions to extract

## Key Terminology

- **GHMM**: Generalized Hidden Markov Model - stochastic process with hidden states
- **Belief State**: Probability distribution over hidden states given observed sequence
- **MSP**: Mixed State Presentation - representation of belief states as tree structure
- **Markov Approximation**: Finite-order Markov chain approximating GHMM dynamics
- **Activation Analysis**: Regression mapping neural activations to belief states
- **Residual Stream**: In transformers, the sum of all layer outputs (from TransformerLens)

## Important Notes

- The codebase uses `uv` package manager instead of `pip`
- Training requires GPU, originally run on H100
- Regression analysis is computationally intensive (can take hours per model)
- Default analysis uses Markov order 3 for classical baselines
- K-fold cross-validation (N_SPLITS=10) ensures robust performance estimates
- The paper focuses on 4-layer networks specifically
- Figure generation scripts download pre-computed results from HuggingFace by default
